# HighwayEnv 教学进度维护

让下一次教学准确接续：保存本次真实新增的教学、代码、运行和理解事实，分别说明执行者和依据。按教学节点在当前对话中维护，不运行后台时钟，也不自行创建定时任务。

## 触发与范围

- 小节结束、收到新实验结果或理解反馈、解决报错、切换课题以及用户暂停时，在本轮结束前执行保存。用户恢复上课时先读取接续点；读取本身不产生新的完成记录。
- 使用当前上下文的 HighwayEnv 教学根目录，核对其 `AGENTS.md`、`PROGRESS.md` 和 `learning/LEARNING_LOG.md`。当前项目不明确时先确认位置，不在其他仓库创建教学档案。
- 维护 `PROGRESS.md` 和 `learning/LEARNING_LOG.md`；必要时归档有价值的日志至 `learning/evidence/`。路线图与教学约定只在实际教学方向或保存要求改变时更新。
- 当前用户偏好是按教学小节/新结果维护；固定时间后台执行需要另有明确请求和实际调度配置。本技能的自动选择不等于定时运行。

## 根据新增证据更新

1. 读取项目教学约定、当前进度和历史记录末尾，再查看本课相关代码、用户输出和会话中的新反馈。无需每次重读整套源码或路线图。
2. 将信息按来源分开：实际文件内容、用户提供的运行日志、用户自己的说明、助手讲解，以及助手独立验证。无法访问的证据明确记为待复核。
3. 判断是否有实质变化。相同日志、重复解释、无新信息的状态询问和维护工具本身运行，不应反复生成学习完成记录。没有新事实时保持文档不变。
4. 更新 `PROGRESS.md` 的对应字段：实际更新时间及本地时区、当前唯一课题、代码状态、实践证据、理解证据、尚未确认的问题、下一次具体从哪里继续。保留其他仍有效的信息。
5. 在 `learning/LEARNING_LOG.md` 追加本次必要的历史事实，沿用现有格式。归档日志时注明来源、执行者及已知参数；未知种子、退出原因和执行时间不补猜。
6. 写入前核对最新文件，合并用户或其他会话刚产生的更改；使用局部修改，不用旧快照覆盖整份记录。用户在助手检查期间新增代码时，以最后检查为准，保留变化过程。
7. 检查更新时间、当前状态与下一步是否一致，所引用文件是否存在，数字是否与日志匹配。有修改时简短告知保存结果；写入失败就说明失败，不能宣称已保存。

## 证据如何影响状态

| 新事实 | 可以记录 | 仍不能推断 |
| --- | --- | --- |
| 助手给出一段示例或解释 | 已讲解/已提供修改方法 | 用户已经修改、运行或理解 |
| 文件存在相关配置或实现 | 已修改，等待运行证据 | 已经运行成功或独立完成 |
| 用户提供真实结果或描述看到的现象 | 已收到用户运行结果，注明范围 | 已会从零实现或在所有路况有效 |
| 用户说“懂了” | 用户表示理解 | 已经独立解释和迁移应用 |
| 用户提供自己的解释或修改理由 | 按回答记录具体理解及待澄清点 | 未涉及的知识也已掌握 |
| 助手单独做实验通过 | 助手验证的条件和结论 | 学习者已完成同一实验 |

没有证据写“待核对”，不用它推断学习者不会。不代写用户预测或答案，不用代码完成、文档生成、测试通过来自动推进学习状态。

## 保持接续可靠

- 当前进度以 `PROGRESS.md` 为准；历史记录保留当时事实，路线图不复制一套进行中状态。
- 下一步给出具体代码位置、操作或待解释现象。已完成的修改不重复要求；尚无运行结果时保持“已修改待运行”。
- 区分完整回合与截断日志，目标速度与实际速度，用户带交通的运行与助手零交通验证。只维护能从当前资料支持的结论。
- 保存记录不顺带修改用户练习代码、启动仿真/训练、安装依赖或进行 Git 提交与推送；这些需要相应的任务范围。
- 不将私人技能文件夹变成第二个进度存储位置。会变化的学习状态只写入项目文档，本技能保留维护方法。
